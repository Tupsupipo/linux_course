Week 4: Replicating week 2's visitor counter

Welcome to my fourth linux project! This site is running on a clone server of the week 2 setup.

In this project, I have replicated the visitor counter from week 2. This site does not increment the counter, but simply mirrors the counter value from week 2's site

There have been {{ result }} visitors on week 2 page

The visitor counter is stored in a MySQL database. Whenever the week 2 page is visited or refreshed, the Flask application updates the counter by executing SQL queries and displays the current total. Counter values are synchronized between the two sites, but only the week 2 site increments the counter.

Create server B by copying server A.

To copy the week 2 server setup, I created a snapshot of the week 2 server and rebuilt it on a new server using CSC's own web interface.

Configure hourly website backups from A to B.

I made a bash script for hourly website backups from A to B. The cron job executes a script that uses rsync to copy the HTML files from the week 2 server to the new server's /srv/backup/www/$date directory. Script also maintains a log file of the backup process and keeps only the last 2 backups, deleting older ones. The script is executed every hour using a cron job.

Configure continuous MariaDB replication from A to B.

For database I did use MySQL instead of MariaDB(Was familiar with it, and started these task before there was info on week2, it was a mistake, but lets go with it now and try to adapt). To make synchronization happen i used MySQL's own tools mysqldump and mysql replication. I made a dedicated replication user and used it exclusively for database replication. Replication account was granted only the necessary privileges for replication purposes and was restricted to connections from server A.

Application users were restricted to read-only access to the database.
